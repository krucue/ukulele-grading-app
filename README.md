## เริ่มใช้งาน — เปิดเว็บแอป (วิธีที่ง่ายที่สุด)

**ดับเบิลคลิก `เปิดโปรแกรมตรวจข้อสอบ.bat`** เท่านั้น ไม่ต้องพิมพ์คำสั่งอะไรเลย
เบราว์เซอร์จะเปิดขึ้นมาเอง แล้วใช้งานทั้งหมดในหน้าเว็บ: กรอกชื่อนักเรียน → ใส่กระดาษคำตอบ
→ กดตรวจ → แก้คะแนนข้อที่ระบบไม่มั่นใจ → กดบันทึก → กด **"ตรวจนักเรียนคนต่อไป"** แล้ววนใหม่
ได้ทั้งห้องโดยไม่ต้องรีเฟรชหน้า (ปุ่มนี้ล้างชื่อและไฟล์ของคนเก่าให้หมด กันกระดาษคนก่อนติดมาด้วย)

**การบันทึกเป็นการ "ต่อแถวใหม่" เสมอ ไม่ได้ทับแถวเดิม** พอบันทึกสำเร็จปุ่มบันทึกจะหายไปเลย
เพื่อไม่ให้เผลอกดซ้ำแล้วได้นักเรียนคนเดียว 2 แถว ถ้าแก้คะแนนหลังบันทึกไปแล้ว ปุ่มจะกลับมา
พร้อมคำเตือนว่ากดแล้วจะเพิ่มแถวใหม่ ต้องไปลบแถวเก่าออกเองในไฟล์/ชีต

**กระดาษคำตอบใส่ได้ 2 ทาง เลือกอย่างใดอย่างหนึ่ง:**

| แบบ | ใส่อย่างไร |
|---|---|
| **ไฟล์สแกน PDF** (สะดวกที่สุด) | สแกนทั้ง 2 หน้ารวมเป็น PDF ไฟล์เดียวแล้วลากมาวางในกรอบบน — ไฟล์ที่ออกจากเครื่องสแกนหรือแอปสแกนบนมือถือใช้ได้เลย ไม่ต้องแปลงเป็นรูปก่อน |
| **รูปแยกทีละหน้า** | ถ่ายด้วยมือถือแล้วลากรูปหน้า 1 / หน้า 2 มาวางในกรอบล่าง (.jpg .png และ .heic จาก iPhone ที่โปรแกรมแปลงให้เอง) · เปิดหน้าเว็บบนมือถือแล้วกดที่กรอบ จะเลือกถ่ายรูปได้เลย |

PDF ที่ใช้ได้ต้องเป็น **ไฟล์ที่สแกนมา** คือแต่ละหน้ามีรูปฝังอยู่ ส่วน PDF ที่พิมพ์ออกมาจาก
Word/Google Docs ใช้ไม่ได้ (ไม่มีรูปให้อ่าน) ระบบจะบอกสาเหตุให้ ไม่ปล่อยให้ตรวจแล้วได้ 0 เฉย ๆ

(บน macOS/Linux หรือถ้าอยากสั่งเอง: `python web_app.py`)

ครั้งแรกที่เปิดในเครื่องใหม่ ตัว `.bat` จะติดตั้งไลบรารีที่ต้องใช้ให้เองรอบเดียว (ใช้เวลา 2-3 นาที) ไม่ต้องพิมพ์คำสั่งเอง — ถ้าสั่งรันเองบน macOS/Linux ให้พิมพ์ `pip install -r requirements.txt` ก่อนหนึ่งครั้ง

**เปิดครั้งแรกใช้ได้ทันทีโดยไม่ต้องมี API key** — เลือกโหมด "ลองใช้งานก่อน" จะใช้คำตอบตัวอย่าง
แสดงให้ดูว่าหน้าตาผลลัพธ์เป็นอย่างไร ไม่ต้องมีรูป ไม่ต้องตั้งค่าอะไรเลย
โหมด "ตรวจจริง" จะกดไม่ได้จนกว่าจะตั้งค่าใน `settings.json` ครบ (ดูหัวข้อถัดไป) —
ตั้งใจให้เป็นแบบนี้ เพื่อไม่ให้ครูเผลอเอาคะแนนจากโหมดจำลองไปใช้จริง

หน้าต่างสีดำที่เปิดขึ้นมาคือตัวเซิร์ฟเวอร์ **ต้องเปิดค้างไว้ตลอดเวลาที่ใช้งาน** ปิดเมื่อไหร่เว็บก็ดับ

เซิร์ฟเวอร์ผูกกับ `127.0.0.1` เท่านั้น = เครื่องอื่นในวงแลนเปิดไม่ได้ ตั้งใจให้เป็นแบบนี้
เพราะรูปกระดาษคำตอบมีชื่อและลายมือนักเรียนอยู่ ไม่ควรออกจากเครื่องครูไปไหน
(ถ้าอยากเปิดจากมือถือ ดูหัวข้อ "ใช้งานจากมือถือ" ข้างล่าง)

### ใช้งานจากมือถือ

ดับเบิลคลิก **`เปิดโปรแกรม (ใช้กับมือถือได้).bat`** แทนไฟล์ปกติ แล้วสแกน QR ที่ขึ้นใน
หน้าต่างสีดำด้วยมือถือ ไม่ต้องพิมพ์ IP เอง

มือถือเป็นแค่**จอ** เท่านั้น ตัวตรวจจริงยังเป็นคำสั่ง `claude` บนคอมเครื่องเดิม
**คอมต้องเปิดค้างไว้เสมอ** ปิดเมื่อไหร่มือถือก็ใช้ไม่ได้

**ต้องตั้ง `access_code` ใน `settings.json` ก่อน ไม่งั้นโปรแกรมไม่ยอมเปิดเลย**

```json
"access_code": "ตั้งรหัสของครูเอง อย่างน้อย 6 ตัว",
```

เลือกหยุดโปรแกรมไปเลยแทนที่จะเตือนแล้วเปิดต่อ เพราะทันทีที่ผูกกับ `0.0.0.0`
ใครที่ต่อ Wi-Fi วงเดียวกัน (รวมนักเรียน) ก็เปิดดูคะแนนได้หมด และคำเตือนที่วิ่งผ่านไปใน
หน้าต่างสีดำครูจะไม่ทันเห็น แล้วเปิดทิ้งไว้ทั้งวันโดยไม่รู้ตัว

ด่านรหัสผ่านกันทั้งหน้าเว็บและ `/api/` — ยิงตรงเข้า `/api/save` โดยไม่ล็อกอินจะได้ 401
ไม่ใช่กันแต่หน้า HTML แล้วปล่อย API ผ่าน (ดูเทสใน `tests/test_webapp.py`)

**การปิด-เปิดโปรแกรมไม่เตะมือถือออกจากระบบ** กุญแจเซ็นคุกกี้ผูกกับตัวรหัสผ่าน ไม่ได้สุ่มใหม่
ทุกครั้งที่เปิด เพราะแถบเตือน "โปรแกรมถูกอัปเดต" สั่งให้ปิดแล้วเปิดโปรแกรมใหม่อยู่เรื่อย ๆ
ถ้าเตะออกทุกครั้งจะกวนเกินไป — **แต่พอเปลี่ยน `access_code` เมื่อไหร่ ทุกเครื่องที่ล็อกอิน
ค้างไว้หลุดทันที** ซึ่งเป็นจังหวะที่ต้องการให้หลุดจริง ๆ

ถ้าเซสชันหลุดตอนมีผลตรวจค้างอยู่บนจอ (เช่นเปลี่ยนรหัสระหว่างที่ครูกำลังไล่แก้คะแนน)
หน้าเว็บ**จะไม่เด้งออกไปหน้าล็อกอิน** เพราะผลตรวจที่ยังไม่ได้บันทึกจะหายทั้งชุด
มันจะขึ้นข้อความบอกให้ไปล็อกอินที่แท็บใหม่แล้วกลับมากดบันทึกแทน

**ครั้งแรกที่เปิด Windows จะถามว่าจะให้ Python ใช้เครือข่ายไหม ต้องกด Allow และติ๊ก
Private networks** ไม่งั้นมือถือจะเข้าไม่ได้

| อยากใช้ที่ไหน | ต้องทำอะไรเพิ่ม |
|---|---|
| Wi-Fi เดียวกับคอม | ไม่ต้องทำอะไรเพิ่ม ใช้ URL วงแลนที่โปรแกรมพิมพ์ให้ได้เลย |
| นอกโรงเรียน / เน็ตมือถือ | ติดตั้ง [Tailscale](https://tailscale.com) ทั้งบนคอมและมือถือ ล็อกอินบัญชีเดียวกัน แล้วใช้ URL ตัวที่ขึ้นว่า "ใช้ได้ทุกที่" |

เลือก Tailscale แทนการทำ tunnel สาธารณะ (เช่น Cloudflare Tunnel) เพราะ tunnel ให้ URL
ที่ใครเจอก็เข้าได้ ส่วน Tailscale ไม่มี URL สาธารณะเลย เห็นได้เฉพาะเครื่องที่ล็อกอิน
บัญชีเดียวกัน และยังใช้ได้แม้ Wi-Fi โรงเรียนจะเปิด client isolation ไว้ (ซึ่งทำให้วิธี
วงแลนใช้ไม่ได้เลย)

### ตั้งค่าครั้งเดียวใน settings.json

คัดลอก `settings.example.json` เป็น `settings.json` แล้วเติมค่า — ตั้งครั้งเดียวอยู่ถาวร
ไม่ต้อง `export ANTHROPIC_API_KEY=...` ใหม่ทุกครั้งที่เปิด terminal เหมือนเมื่อก่อน
(`settings.json` ถูก `.gitignore` ไว้แล้ว ไม่หลุดขึ้น GitHub)

**ถ้าเครื่องนี้ติดตั้ง Claude Code ไว้แล้ว (มีคำสั่ง `claude`) ไม่ต้องตั้งอะไรเลยก็ตรวจจริงได้**
โปรแกรมจะเรียกผ่านคำสั่ง `claude` โดยใช้สิทธิ์จาก subscription ที่ล็อกอินไว้ ไม่ต้องมี API key
ไม่ต้องเติมเครดิตแยก (วัดจริง: ~55 วินาทีต่อนักเรียน 1 คน)

ใส่ `anthropic_api_key` เมื่ออยากให้เร็วขึ้นหรือจะเอาไปรันบนเครื่องที่ไม่มี Claude Code —
มีคีย์แล้วโปรแกรมจะเลือกใช้คีย์ก่อนเสมอ

| ค่า | ใช้ทำอะไร | ไม่ใส่แล้วเป็นอย่างไร |
|---|---|---|
| `anthropic_api_key` | ใช้ทั้ง **อ่านลายมือจากรูป** และ **ตรวจให้คะแนนทุกข้อ** | ถ้าเครื่องมีคำสั่ง `claude` ก็ยังตรวจจริงได้ตามปกติ · ถ้าไม่มีทั้งคู่ โหมดตรวจจริงจะกดไม่ได้ |
| `ocr_provider` | `auto` = มีคีย์ใช้คีย์ ไม่มีก็ใช้คำสั่ง `claude` · บังคับได้ด้วย `api` หรือ `cli` | ใช้ `auto` |
| `claude_model` | เลือกโมเดล | ใช้ `claude-opus-5` (อ่านลายมือแม่นสุด) · อยากประหยัดเปลี่ยนเป็น `claude-sonnet-5` ได้ |
| `google_credentials_path` | service account ของ Google — ใช้เฉพาะตอนบันทึกลง Google Sheets | ไม่กระทบการตรวจเลย บันทึกลงไฟล์ CSV ได้ตามปกติ |
| `sheet.mode` | `csv` = ลงไฟล์ในเครื่อง / `google` = ลง Google Sheets | ใช้ `csv` |
| `sheet.csv_path` | ไฟล์ปลายทางเมื่อใช้โหมด csv | ใช้ `ข้อมูล/ผลตรวจ/ผลตรวจ.csv` (สร้างโฟลเดอร์ให้เอง) |
| `sheet.spreadsheet_id` | รหัสใน URL ของ Sheet | ถ้าเลือก `google` แล้วไม่ใส่ จะขึ้นเตือนในหน้า "สถานะระบบ" |
| `sheet.tab_name` | ชื่อแท็บในชีตที่จะเขียนลง | ใช้ `ผลตรวจ` · **ไม่มีแท็บนี้โปรแกรมสร้างให้เอง** ไม่ต้องไปเปลี่ยนชื่อ `Sheet1` ในชีต |

ขอคีย์ที่ [console.anthropic.com](https://console.anthropic.com) > API keys > Create key
แล้ววางลงในช่อง `anthropic_api_key` (คีย์ขึ้นต้นด้วย `sk-ant-`) ต้องเติมเครดิตในบัญชีก่อน
คีย์ถึงจะใช้ได้ — ค่าใช้จ่ายประเมินคร่าว ๆ อยู่ราวไม่กี่บาทต่อนักเรียนหนึ่งคน (ตรวจ 1 คน =
ส่งภาพไปอ่าน 12 ครั้ง ข้อละครั้ง บวกอีก 1 ครั้งสำหรับตรวจข้อบรรยาย) ถ้าเปลี่ยนไปใช้
`claude-sonnet-5` จะถูกลงอีก ตัวเลขจริงดูได้ที่หน้า Usage ใน console หลังตรวจจริงไปแล้วสัก 2-3 คน

### บันทึกคะแนนลง Google Sheets

ค่าเริ่มต้นบันทึกลงไฟล์ CSV ในเครื่อง ซึ่งใช้งานได้เลยไม่ต้องตั้งอะไร ถ้าอยากให้ลง
Google Sheets แทน (เปิดดูจากที่ไหนก็ได้ แชร์ให้คนอื่นดูได้) ทำตาม 5 ขั้นนี้ครั้งเดียวจบ

**1. ติดตั้งไลบรารีของ Google** — เปิด PowerShell ที่โฟลเดอร์นี้แล้วพิมพ์

```bash
pip install -r requirements-google.txt
```

**2. สร้าง service account** ที่ [console.cloud.google.com](https://console.cloud.google.com)

- สร้างโปรเจกต์ใหม่ (ตั้งชื่ออะไรก็ได้)
- เปิดใช้ **Google Sheets API** ที่ APIs & Services > Library > ค้นหา "Google Sheets API" > Enable
- ไปที่ APIs & Services > Credentials > Create credentials > **Service account** > ตั้งชื่อ > Done
- คลิกที่ service account ที่เพิ่งสร้าง > แท็บ **Keys** > Add key > Create new key > เลือก **JSON** > Create

ไฟล์ `.json` จะถูกดาวน์โหลดมา **เก็บไว้นอกโฟลเดอร์โปรเจกต์** (เช่นใน `Documents`)
ไฟล์นี้คือกุญแจเข้าบัญชี ห้ามให้ใครและห้ามอัปขึ้น GitHub

**3. สร้าง Google Sheet เปล่า** แล้วคัดลอกรหัสจาก URL

```
docs.google.com/spreadsheets/d/1AbC...ยาว ๆ ตรงนี้คือ spreadsheet_id.../edit
```

**4. แชร์ชีตให้ service account** — ขั้นนี้คนลืมบ่อยที่สุด

เปิดไฟล์ `.json` ที่ดาวน์โหลดมา หาบรรทัด `"client_email"` จะได้อีเมลหน้าตาแบบ
`ชื่อ@โปรเจกต์.iam.gserviceaccount.com` เอาอีเมลนั้นไปกดปุ่ม **"แชร์"** ในชีต
แล้วให้สิทธิ์ **ผู้แก้ไข (Editor)**

ถ้าลืมขั้นนี้ Google จะตอบ 403 ซึ่งอ่านไม่รู้เรื่อง — โปรแกรมดักไว้แล้วและจะบอก
อีเมลที่ต้องแชร์ให้มาตรง ๆ ในข้อความ error

**5. แก้ `settings.json`** 3 บรรทัด

```json
"google_credentials_path": "C:/Users/ชื่อผู้ใช้/Documents/ชื่อไฟล์.json",
"sheet": {
  "mode": "google",
  "spreadsheet_id": "รหัสที่คัดลอกมาจากขั้นที่ 3"
}
```

เปิดโปรแกรมใหม่ **หน้าต่างสีดำจะลองต่อชีตให้ตั้งแต่ตอนเปิด** ถ้าต่อได้จะขึ้นว่า
`ต่อ Google Sheets ได้ เขียนลงแท็บ "ผลตรวจ"` ถ้าต่อไม่ได้จะบอกสาเหตุพร้อมวิธีแก้ทันที
ตั้งใจให้เช็คตั้งแต่ตอนเปิด ไม่ใช่ไปรู้เอาตอนกดบันทึกซึ่งเป็นขั้นตอนสุดท้ายหลังตรวจ
กระดาษไปแล้วเป็นนาที

**ไม่ต้องสร้างแท็บชื่อ "ผลตรวจ" เอง** โปรแกรมสร้างให้ และเขียนหัวตารางให้เฉพาะตอน
ที่แท็บยังว่าง ไม่เขียนทับของเดิม

หน้าเว็บมีปุ่ม **"สถานะระบบ"** มุมขวาบน กดดูได้ตลอดว่าตอนนี้ต่อของจริงหรือของจำลองอยู่
และถ้า `settings.json` มีปัญหา (JSON เสีย, path ไม่มีจริง) จะเด้งบอกตรงนั้นเลย

### อัปเดตโปรแกรมแล้วต้องเปิดใหม่เสมอ

หน้าเว็บโหลดไฟล์หน้าจอใหม่จากดิสก์ทุกครั้ง แต่โค้ดฝั่งเซิร์ฟเวอร์ถูกอ่านเข้าหน่วยความจำ
ตอนเปิดโปรแกรมครั้งเดียว **ถ้าอัปเดตโปรแกรมระหว่างที่เปิดหน้าต่างสีดำค้างไว้ หน้าเว็บจะ
เป็นตัวใหม่แต่ตัวโปรแกรมยังเป็นตัวเก่า** อาการที่เคยเจอจริงคือปุ่ม "ตรวจจริง" กดไม่ได้
ทั้งที่โค้ดใหม่ทำได้แล้ว พอกดไม่ติดฟอร์มก็ถูกส่งเป็นโหมดลองใช้งานโดยครูไม่รู้ตัว

ตอนนี้หน้าเว็บเช็คให้เองแล้ว ถ้าเจอว่าไฟล์โค้ดใหม่กว่าตัวที่กำลังรันอยู่ จะขึ้นแถบสีแดง
บนสุดบอกให้ปิดหน้าต่างสีดำแล้วเปิด `เปิดโปรแกรมตรวจข้อสอบ.bat` ใหม่

### ระวัง: โหมด "ลองใช้งาน" ไม่ได้อ่านกระดาษที่อัปโหลด

โหมดลองใช้งานหยิบคำตอบจากไฟล์ตัวอย่าง `demo/mock_ocr_answers.json` มาแสดงเสมอ ไม่ว่าจะ
ใส่กระดาษของใครก็ได้คำตอบชุดเดิมทุกครั้ง (เช่นข้อ 2.3 เป็น "4 สาย" ตลอด) มีไว้ดูหน้าตา
ผลลัพธ์เท่านั้น — **เคยมีคนเข้าใจผิดว่าเป็นผลจากกระดาษจริงมาแล้ว** ตอนนี้จึงมีแถบเตือน
ตัวใหญ่บนผลลัพธ์ และ**ซ่อนปุ่มบันทึกทิ้งไปเลย** บันทึกลงไฟล์คะแนนไม่ได้

ถ้าเห็นแถบสีส้มนี้ แปลว่ากำลังอยู่ในโหมดลองใช้งาน ให้เลือก "ตรวจจริง" แทน

### เริ่มตรวจจริงวันแรก — ทำ 4 ขั้นนี้

1. **คัดลอก `settings.example.json` เป็น `settings.json`** แล้วใส่คีย์ในช่อง `anthropic_api_key`
   (คีย์เดียวจบ ไม่ต้องตั้งอย่างอื่น) แล้วเปิดโปรแกรมใหม่ ให้ปุ่ม **"ตรวจจริง"** กดได้
2. **ตรวจกระดาษที่ครูเคยตรวจด้วยมือไปแล้ว 1-2 ใบก่อน** แล้วเทียบคะแนนกับที่ตรวจเอง
   ถ้าตรงกันค่อยเดินหน้าตรวจทั้งห้อง ถ้าเพี้ยนเป็นบางข้อให้ดูช่อง "คำตอบที่อ่านได้"
   ในหน้าเว็บว่าอ่านลายมือผิด หรือกรอบตัดภาพ (`config/regions.json`) เลื่อน
3. **ข้อที่ขึ้นว่า "ต้องตรวจสอบ" ครูต้องดูเองทุกข้อ** ระบบตั้งใจไม่ตัดสินเองเมื่อไม่มั่นใจ
   — อ่านลายมือเด็กด้วยเครื่องยังไงก็มีพลาด จุดนี้คือด่านที่กันคะแนนผิดไปถึงมือนักเรียน
4. **สแกนให้เหมือนกันทุกใบเท่าที่ทำได้** — ระบบดัดภาพให้ทับใบอ้างอิงเองอยู่แล้ว
   แต่ยิ่งสแกนเหมือนกัน การจับคู่ยิ่งแม่นและไม่มีใบไหนถูกตีกลับ

### ทำไมต้องให้ Claude ตัดสินคะแนนทุกข้อ ไม่ใช่แค่ข้อบรรยาย

ตอนตรวจจริง โปรแกรมยิง Claude 2 ครั้งต่อนักเรียน 1 คน: ครั้งแรกอ่านลายมือทั้ง 12 ข้อ
จากภาพแผ่นเดียว ครั้งที่สองตัดสินว่าคำตอบแต่ละข้อใกล้เคียงเฉลยกี่ % แล้วส่งตัวเลขนั้น
เข้า pipeline เดิม — **ขั้นคะแนน (tier) การตั้งธง "ต้องตรวจสอบ" และไฟล์ผลลัพธ์
ยังเป็นของระบบตามเกณฑ์ในไฟล์เฉลยเหมือนเดิมทุกอย่าง**

เหตุผลที่ต้องให้ตัดสินทุกข้อ ไม่ใช่เฉพาะข้อ 4: ข้อสอบชุดนี้แจกทั้งฉบับภาษาไทยและอังกฤษ
เด็กจึงตอบคนละภาษากับเฉลยได้ การวัดความใกล้เคียงระดับตัวอักษรจะให้ 0 กับคำตอบที่ถูกต้อง
เต็ม ๆ (วัดจริง: เด็กตอบ `Play openly, no pressing` ซึ่งตรงเฉลย "ดีดสายเปล่า ไม่ต้องกด"
เป๊ะ แต่ได้ความใกล้เคียงแค่ 3%)

ถ้าขั้นนี้ล้ม (เน็ตหลุด/CLI ล็อกเอาต์) ระบบจะถอยไปวัดแบบเทียบตัวอักษรและ**ขึ้นคำเตือน
ให้ครูรู้** ว่าคะแนนจะเข้มผิดปกติ ต้องตรวจซ้ำทุกข้อก่อนบันทึก

### ใบอ้างอิง — สิ่งที่ทำให้กรอบตัดคำตอบไม่เลื่อน

เครื่องสแกนครอบกระดาษมาไม่เท่ากันทุกใบ (วัดจากของจริง 4 ไฟล์: อัตราส่วนภาพออกมาตั้งแต่
0.650 ถึง 0.693 ทั้งที่เป็นกระดาษ A4 แผ่นเดียวกัน) ถ้าใช้พิกัดคงที่ตัดภาพตรง ๆ กรอบคำตอบ
จะเลื่อนไปคนละแถวจนตัดโดนหัวตารางแทนคำตอบ — เคยเกิดจริงกับข้อ 5.1-5.4

ระบบจึงต้องมี **ใบอ้างอิง** คือกระดาษข้อสอบ *เปล่า* ที่สแกนเก็บไว้ครั้งเดียว เก็บใน
`config/reference/` เวลาตรวจ กระดาษของนักเรียนแต่ละใบจะถูกจับคู่กับใบอ้างอิงด้วยลายพิมพ์
บนหน้ากระดาษ (หัวข้อ เส้นตาราง เส้นบรรทัด) แล้วดัดให้ทับกันพอดีก่อนตัดภาพ

```bash
pip install -r requirements-tools.txt                     # ครั้งเดียว ใช้เรนเดอร์ PDF ต้นฉบับ
python tools/make_reference.py ข้อมูล/ข้อสอบ/Final_exam_G6_EN.pdf --ชื่อ อังกฤษ
python tools/make_reference.py ข้อมูล/ข้อสอบ/กระดาษเปล่า.pdf --ชื่อ ไทย   # ถ้าข้อสอบมีหลายเวอร์ชัน
python tools/check_regions.py ข้อมูล/กระดาษนักเรียน/61/*.pdf   # ตรวจซ้ำด้วยกระดาษจริงหลายใบ
```

ใส่ได้ทั้ง **PDF ต้นฉบับที่ใช้พิมพ์ข้อสอบ** (ดีที่สุด — ไม่มีความเพี้ยนจากเครื่องสแกนเลย)
ไฟล์ที่สแกนกระดาษเปล่ามา หรือรูปแยกหน้า

ข้อควรรู้:

- **ใบอ้างอิงต้องเป็นข้อสอบฉบับเดียวกับที่นักเรียนทำ** ถ้าห้องเดียวกันแจกทั้งฉบับภาษาไทย
  และภาษาอังกฤษ ต้องสแกนเปล่าทั้งสองฉบับ (ใช้ `--ชื่อ`) โปรแกรมจะลองทุกเวอร์ชันแล้วเลือกใบ
  ที่ทับได้ดีที่สุดเอง — ถ้าใช้ผิดฉบับ ระบบจะตีกลับ ไม่ตรวจให้แบบผิด ๆ
- **สร้างใบอ้างอิงใหม่เมื่อไหร่ ต้องวัดพิกัดใน `config/regions.json` ใหม่ด้วยเสมอ**
  เพราะพิกัดทั้งหมดอ้างอิงระบบพิกัดของใบนั้น
- ใบอ้างอิงเป็นกระดาษเปล่า ไม่มีชื่อหรือลายมือนักเรียน จึง commit ขึ้น repo ได้
  (`.gitignore` เปิดช่องไว้ให้เฉพาะโฟลเดอร์นี้)
- ยังไม่มีใบอ้างอิงก็ยังตรวจได้ ระบบจะถอยไปใช้วิธีเดิม (ย่อทั้งใบ) พร้อมขึ้นคำเตือนว่ากรอบ
  ตัดคำตอบอาจเลื่อน — ใช้ดูผลได้ แต่ไม่ควรใช้ตัดสินคะแนนจริง

### ยังไม่มี anthropic_api_key ก็ตรวจได้ — ทางที่ให้คนอ่านลายมือแทน

`subscription ของ Claude Code ใช้แทน API key ไม่ได้` เป็นคนละระบบบิลกัน ถ้ายังไม่ได้เปิด
API key ยังมีทางตรวจที่ได้คะแนนแบบเดียวกันทุกประการ ต่างแค่ "ใครเป็นคนอ่านลายมือและ
ตัดสินความใกล้เคียง" — ส่วนการเทียบขั้นคะแนน การตั้งธง "ต้องตรวจสอบ" และไฟล์ผลลัพธ์
ยังเป็นของระบบตามเกณฑ์ในไฟล์เฉลยเหมือนเดิมทั้งหมด

```bash
# 1) ทำแผ่นภาพคำตอบ 1 แผ่นต่อคน (ผ่านการจับคู่ใบอ้างอิงและตัดภาพเหมือนตอนตรวจจริง)
python tools/make_crop_sheets.py ข้อมูล/กระดาษนักเรียน/61/*.pdf --out ข้อมูล/ภาพคำตอบ

# 2) เปิดไฟล์ ข้อมูล/ภาพคำตอบ/<ชื่อ>.png อ่านคำตอบ แล้วกรอกลง <ชื่อ>.json ที่อยู่ข้าง ๆ
#    text = คำตอบที่อ่านได้ · confidence = มั่นใจว่าอ่านถูกแค่ไหน (0-1)
#    percent = ใกล้เคียงเฉลยกี่ % (0-100) · reasoning = เหตุผลสั้น ๆ ให้ครูอ่าน

# 3) คิดคะแนนด้วยเกณฑ์เดิมแล้วบันทึกผล
python grade_exam.py --pdf ข้อมูล/กระดาษนักเรียน/61/929.pdf \
    --answers ข้อมูล/ภาพคำตอบ/929.json \
    --student-name "ชื่อนักเรียน" --student-no 12 --student-class 6/1 \
    --sheet csv --sheet-path ข้อมูล/ผลตรวจ/ผลตรวจ-6-1.csv
```

ใครกรอกไฟล์ json ก็ได้ — ครูอ่านเอง ผู้ช่วยอ่านให้ หรือเปิดแผ่นภาพใน Claude Code
แล้วให้ช่วยอ่านกับตัดสินให้ก็ได้ (วิธีหลังคือที่ใช้ตรวจห้อง 6/1 ชุดแรกจริง ๆ)

ข้อควรรู้: ถ้าเป็นข้อบรรยาย (`llm_semantic` เช่นข้อ 4) **ต้องใส่ `percent` เสมอ** ระบบ
คิดเองไม่ได้ถ้าไม่มี API key — จะฟ้องออกมาตรง ๆ ไม่ปล่อยให้ได้ 0 เงียบ ๆ

## ตรวจตำแหน่ง crop ด้วยตาก่อนใช้จริง

`config/regions.json` วัดพิกัดจาก **ไฟล์ที่สแกนจากกระดาษจริง** แล้วตรวจสอบด้วยตาทีละข้อแล้ว
(ชุดแรกวัดจาก PDF ที่ render จาก out.docx ซึ่งผิดทุกข้อเมื่อเจอกระดาษจริง — ดูหัวข้อข้อจำกัด)
แต่เครื่องพิมพ์/สแกนเนอร์ของแต่ละโรงเรียนยังต่างกันได้ ควรตรวจสอบก่อนใช้จริงเสมอ:

```bash
python tools/calibrate_regions.py หน้า1_ที่พิมพ์จริง.jpg หน้า2_ที่พิมพ์จริง.jpg
```

จะได้ไฟล์ `*_boxes.jpg` ที่วาดกรอบแดงทับตำแหน่งที่จะ crop ไว้ เปิดเทียบกับกระดาษจริงด้วยตา
ถ้ากรอบไม่ตรงช่องคำตอบ ให้แก้ตัวเลขใน `config/regions.json` ตรงๆ (หน่วยพิกเซล `[left, top, right, bottom]`)

อีกตัวคือ `tools/check_regions.py` ที่วัดเป็นตัวเลขให้ ใส่ไฟล์สแกนหลายใบพร้อมกันได้ —
สำคัญตรงที่ **ใบเดียวผ่านไม่ได้แปลว่าใช้ได้ทั้งห้อง** ต้องลองหลายใบถึงจะรู้ว่าพิกัดนิ่งจริง

```bash
python tools/check_regions.py สแกน1.pdf สแกน2.pdf สแกน3.pdf
```

รายงานต่อข้อว่ามีหมึกอยู่ในกรอบเท่าไร (0% = กรอบตกบนที่ว่าง คืออาการของพิกัดผิด) และ
คำตอบแตะขอบซ้าย/ขวาเท่าไร (สูง = ถูกตัดหัวหรือท้ายทิ้ง) พร้อมเซฟภาพ crop ทุกข้อมาให้ดู
ไม่นับขอบบน/ล่างเพราะหางตัว p g y ล้นนอกช่องตารางเป็นเรื่องปกติที่ OCR ยังอ่านได้
ตัวเลขเป็นแค่ตัวช่วยเล็ง **ยังต้องเปิดภาพ crop ดูด้วยตาเสมอ** เพราะกรอบที่ตกผิดที่แต่ดัน
มีหมึกพอดี (เช่นไปตกบนคำถามแทนคำตอบ) จะผ่านทุกเกณฑ์ตัวเลขโดยไม่มีอะไรฟ้อง

**ตั้งเครื่องสแกนให้ปิด auto-crop แล้วใช้ขนาดคงที่ (A4) เสมอ** — ไฟล์ที่ใช้ calibrate ชุดนี้
เปิด auto-crop ไว้ แล้วได้หน้า 1 ขนาด 2701x3985 (อัตราส่วน 0.678) กับหน้า 2 ขนาด 2837x3789
(0.749) ทั้งที่เป็นกระดาษ A4 (0.707) ใบเดียวกัน สแกนรอบเดียวกัน แปลว่าเครื่องครอบมาไม่เท่ากัน
แม้แต่ในไฟล์เดียว ถ้าปล่อยไว้ พิกัดจะเพี้ยนตามความหนักเบาที่เครื่องครอบกระดาษแต่ละใบ และ
`align.py` ก็ช่วยไม่ได้ เพราะกระดาษเต็มเฟรมจนไม่เหลือพื้นหลังให้หาขอบ (`corners_found=False`)

## ตรวจ lint ก่อน commit

```bash
pip install ruff
python -m ruff check .         # ตรวจอย่างเดียว — ตอนนี้ผ่านหมด ไม่มี error ค้าง
python -m ruff check . --fix   # แก้อัตโนมัติเท่าที่แก้ได้
```

`ruff.toml` ล็อกไว้ 2 อย่าง: `target-version = "py310"` และรายการกฎที่เปิดใช้ (`select`)
เขียนไว้ชัดเจน เพื่อให้ผลตรวจเหมือนเดิมไม่ว่าจะติดตั้ง ruff เวอร์ชันไหน

กฎที่จงใจ**ปิด**ไว้ พร้อมเหตุผล:

| กฎที่ปิด | เหตุผล |
|---|---|
| `E501` (บรรทัดยาว) | โค้ดเดิมมีบรรทัดยาวถึง 266 ตัวอักษร การจัดบรรทัดใหม่เป็นเรื่องของ formatter ไม่ใช่ lint |
| `RUF001/002/003` (unicode กำกวม) | โค้ดเบสเป็นภาษาไทยทั้งหมด กฎนี้จะเตือนแทบทุกบรรทัด |
| `T20` (`print`) — เฉพาะ `tests/`, `demo/`, `tools/` | สคริปต์เหล่านี้รันจาก command line และใช้ `print` เป็นช่องทางแสดงผลจริง (ใน `grading/` ยังห้ามอยู่) |
| `TRY003` (ข้อความ error ยาว) | ข้อความใน `raise` เป็นภาษาไทยที่เขียนให้ครูอ่านแล้วแก้ปัญหาได้เอง ตั้งใจให้ยาว |
| `A002`, `ARG001/002` — เฉพาะ `tests/test_real_integrations_mocked.py` | ไฟล์นี้ปลอม SDK ของ Google ต้องคง signature ให้ตรงของจริงเป๊ะ (พารามิเตอร์ชื่อ `range` บัง builtin และหลายตัวรับไว้เฉย ๆ) |

กฎที่เปิดเพิ่มภายหลังและเก็บกวาดจนสะอาดแล้ว: `S` (ความปลอดภัย), `RET`, `PERF`, `ARG`, `A`, `TRY`
โดย `S108` จับบั๊กจริงได้ 3 จุด — โค้ดเขียนไฟล์ชั่วคราวลง `/tmp/` ซึ่ง **ไม่มีอยู่บน Windows**
`cv2.imwrite()` จึงคืน `False` เขียนไม่สำเร็จเงียบ ๆ แก้เป็น `tempfile.gettempdir()` แล้ว

## CI อัตโนมัติ

`.github/workflows/ci.yml` รันทุกครั้งที่ push เข้า `main` และทุก pull request รวม 6 job:

| job | ทำอะไร |
|---|---|
| `ruff` | `ruff check .` ด้วย ruff เวอร์ชันที่ปักไว้ (0.16.5) ให้ผลตรงกับที่รันในเครื่อง |
| `เทสหน้าเว็บ (jsdom)` | `node tests/test_webapp_ui.mjs` บน `ubuntu-latest` อย่างเดียว — ดูพฤติกรรม DOM ล้วน ไม่แตะไฟล์ระบบ จึงไม่มีอะไรต่างระหว่าง OS |
| `เทส` × 4 | รันเทส Python ทั้ง 6 ชุด + `demo/run_demo.py` บน `ubuntu-latest` และ `windows-latest` × Python `3.10` และ `3.13` |

เหตุผลที่ต้องเทสบน **Windows** ด้วยไม่ใช่ใส่เผื่อ — โปรเจกต์นี้เคยมีบั๊ก 2 ตัวที่โผล่เฉพาะ
บน Windows เท่านั้น: `cv2.imwrite()` เขียนไฟล์ลง `/tmp/` ไม่สำเร็จโดยไม่แจ้ง error
และ console cp874 พิมพ์ภาษาไทยแล้วโปรแกรมตาย ทั้งสองอย่างรันบน Linux ผ่านฉลุย

เหตุผลที่ต้องเทส **Python 3.10** — เป็นเวอร์ชันขั้นต่ำที่ README ประกาศไว้ ต้องพิสูจน์ว่ายังจริง

เหตุผลที่ต้องมีเทส **ฝั่งหน้าเว็บ** ทั้งที่โปรเจกต์ตั้งใจไม่พึ่ง build step — `app.js`
ไม่ได้เป็นแค่เปลือกแสดงผลแล้ว มันถือกติกาที่เทสฝั่ง Python มองไม่เห็นเลยเพราะไม่มี request
ยิงออกไป: ตัวกันกดปุ่มบันทึกซ้ำ (กดสองที = นักเรียนคนเดียวมี 2 แถวในชีต ไปโผล่ตอนรวมคะแนน
ปลายภาค ไม่ใช่ตอนตรวจ) และการล้างข้อมูลคนเก่าตอนกด "ตรวจนักเรียนคนต่อไป" (ล้างไม่ครบ =
กระดาษคนก่อนติดไปกับคนใหม่)

สคริปต์เทสทุกไฟล์เรียก `sys.exit(1)` (ฝั่ง node ใช้ `process.exit(1)`) เมื่อมีเคสล้มเหลว
CI จึงจับได้จริงไม่ใช่เขียวหลอก

`.github/dependabot.yml` ตรวจเวอร์ชันใหม่ให้เดือนละครั้ง แล้วเปิด PR มาให้เอง —
ทั้ง GitHub Actions ใน workflow และไลบรารีใน `requirements.txt` รวมเป็น PR เดียวต่อกลุ่ม
เปิด Dependabot security alerts ไว้ด้วย ถ้ามีช่องโหว่จะแจ้งทันทีไม่ต้องรอรอบเดือน

| ปรับแนวและตัดภาพ | `grading/register.py` (จับคู่กับใบอ้างอิงแล้วดัดให้ทับกัน — ทางหลัก) + `grading/align.py` (หาขอบกระดาษ ใช้ตอนยังไม่มีใบอ้างอิง) + `grading/regions.py` (ตัด crop ต่อข้อ) |
| OCR แยกคำตอบทีละข้อ | `grading/ocr.py` |
| ให้คะแนนแบบยืดหยุ่น (string similarity / LLM grader) | `grading/similarity.py`, `grading/llm_grader.py`, `grading/scorer.py` |
| แยกทางตามความมั่นใจ (บันทึกอัตโนมัติ / ส่งครูตรวจ) | logic การสร้าง `flag_reasons` ใน `grading/scorer.py` |
| บันทึกคะแนนลง Google Sheet | `grading/sheets_writer.py`, `grading/pipeline.py` |
| หน้าจอที่ครูใช้จริง | `webapp/` (เว็บแอป) และ `grade_exam.py` (command line) — ทั้งคู่เรียก `pipeline.py` ตัวเดียวกัน |

## ข้อจำกัดที่ควรรู้ก่อนใช้งานจริง

1. **`string_similarity` เป็นแบบตัวอักษร (character-level)** เหมาะกับคำตอบสั้นที่เป็น
   วลี/ประโยค แต่ **ไม่เหมาะกับคำตอบที่เป็นตัวอักษรเดี่ยวหรือสัญลักษณ์เดี่ยว** (เช่น ชื่อสาย
   G/C/E/A) เพราะคำตอบผิดที่ต่างกันแค่ 1 ตัวอักษรอาจถูกวัดว่า "ใกล้เคียง" เกินจริง — ข้อสอบชุดนี้
   แก้แล้วโดยใช้ `keyword_match` กับข้อ 2.3 และ 5.1-5.4 (ดู `tests/test_core.py` ส่วน
   "ข้อจำกัดที่ต้องรู้" ที่พิสูจน์พฤติกรรมนี้ไว้) — เวลาสร้างเฉลยข้อใหม่ ถ้าคำตอบเป็นคำเดียว/
   ตัวอักษรเดี่ยว อย่าใช้ `string_similarity`

   `keyword_match` ถูกเลือกแทน `exact_match` เพราะเด็กเขียนเป็นประโยคกันเยอะ — `"for playing
   string G"` ตอบถูกแต่ `exact_match` ให้ 0 ทันทีเพราะไม่ตรงเป๊ะ ส่วน `keyword_match` เทียบ
   เป็น "คำ" จึงเจอ `G` ในประโยค และยังแยกคำตอบผิดได้อยู่ (`"string C"` ไม่มีคำว่า `g`)
   **ข้อ 5.4 ต้องระวังเป็นพิเศษ** เฉลยคือตัวอักษร `A` ซึ่งชนกับคำนำหน้านาม `a` ในภาษาอังกฤษพอดี
   คำตอบที่มีคำว่า `a` ลอย ๆ จะได้ 100 ทั้งที่ไม่ได้ตอบ — เจอเมื่อไหร่แก้ที่เฉลยข้อนั้น ไม่ใช่ที่โค้ด
2. **`acceptable_answers` ต้องมีทั้งภาษาไทยและภาษาอังกฤษ และควรใส่หลายรูปแบบ** ไม่ใช่แค่
   ประโยคยาวประโยคเดียว

   ข้อสอบชุดนี้แจกทั้งสองภาษา ตอนแรกเฉลยเป็นภาษาไทยล้วน ซึ่งใช้ได้ตราบใดที่เรียก Claude สำเร็จ
   (Claude ตัดสินที่ความหมาย ไม่สนภาษา) แต่ถ้าเรียกไม่สำเร็จ ระบบจะถอยไปวัดความใกล้เคียงแบบ
   เทียบตัวอักษร แล้วเด็กที่ทำฉบับอังกฤษจะได้เกือบ 0 ทั้งใบทั้งที่ตอบถูก (วัดจริง: `"Play openly,
   no pressing"` ตรงเฉลย `"ดีดสายเปล่า ไม่ต้องกด"` เป๊ะ แต่ได้ความใกล้เคียงแค่ 3%) ตอนนี้เฉลย
   มีครบทั้งสองภาษาทุกข้อแล้ว และ `tests/test_core.py` ยึดไว้ไม่ให้ใครลบภาษาใดภาษาหนึ่งทิ้ง

   ที่ยังใส่หลายรูปแบบต่อภาษาด้วย เช่นถ้าเฉลยคือ
   "ดีดสายเปล่า / สายเปิด (ไม่ต้องกด)" ควรใส่ทั้ง `"ดีดสายเปล่า"` และ `"สายเปิด"` แยกกันเป็น
   คนละรายการ เพราะ `best_match_percent` จะเลือกค่าที่ใกล้เคียงที่สุดจากทุกตัวเลือกให้เอง
   การใส่ตัวเลือกสั้นๆ หลายแบบช่วยให้คะแนนแม่นยำขึ้นมากกว่าใส่ประโยคยาวประโยคเดียว
3. **`MockSemanticGrader` ใช้ตัดสินใจจริงไม่ได้** เป็นแค่ keyword overlap หยาบๆ สำหรับรัน
   demo/test แบบ offline เท่านั้น ข้อ 4 (Strumming vs Picking) ต้องสลับไปใช้
   `ClaudeSemanticGrader` ก่อนใช้กับนักเรียนจริง
4. **`grading/align.py` หาขอบกระดาษด้วย contour detection** ใช้ได้ดีเมื่อกระดาษมีขอบเห็นชัดเจน
   (ถ่ายบนพื้นโต๊ะที่สีตัดกับกระดาษ) ถ้าพื้นหลังสีใกล้เคียงกระดาษหรือแสงไม่พอ ควรพิจารณาเพิ่ม
   marker (เช่น QR/ArUco 4 มุม) ตามที่เคยแนะนำไว้ในขั้นตอนออกแบบ logic — แก้ที่ฟังก์ชัน
   `find_page_corners()` จุดเดียวถ้าจะเปลี่ยนวิธี
5. **`grading/pdf_pages.py` ดึงรูปที่ฝังในหน้า ไม่ได้ render หน้า PDF** ไฟล์จากเครื่องสแกน
   และแอปสแกนบนมือถือใช้ได้ (แต่ละหน้าเป็นรูปเต็มหน้าอยู่แล้ว) แต่ PDF ที่พิมพ์ออกมาจาก
   Word/Google Docs ใช้ไม่ได้ เพราะไม่มีรูปให้ดึง — ระบบจะฟ้องออกมาตรง ๆ ไม่คืนภาพเปล่า
   ถ้าวันหนึ่งต้องรองรับ PDF แบบนั้นด้วย ต้องเพิ่มตัว render (pymupdf ที่เป็น AGPL หรือ
   pdf2image ที่ต้องลง poppler แยก) ซึ่งตอนนี้จงใจไม่เอาเข้ามาเพราะหนักเกินความจำเป็น
   หน้าที่มีรูปฝังอยู่หลายรูปจะเลือกรูปที่ใหญ่ที่สุดให้ **พร้อมขึ้นคำเตือน** เพราะเป็นการเดา
6. **`config/regions.json` ผูกกับวิธีสแกน ไม่ใช่ค่าสากล** ชุดแรกวัดจาก PDF ที่ render จาก
   out.docx ด้วยโปรแกรม ซึ่งพอเจอกระดาษที่พิมพ์และสแกนจริง **ผิดทั้ง 12 ข้อ** ไม่มีกรอบไหนตกบน
   ช่องคำตอบเลย และยังระบุว่าข้อ 2.3 อยู่หน้า 2 ทั้งที่อยู่หน้า 1 — ถ้าใช้ไปโดยไม่ตรวจ นักเรียน
   จะได้ 0 กันทั้งห้องโดยระบบไม่ฟ้องอะไรเลย ตอนนี้วัดใหม่จากไฟล์สแกนจริงและตรวจด้วยตาทีละข้อแล้ว
   แต่ยัง **ผูกกับการตั้งค่าสแกนแบบเดิม** ถ้าเปลี่ยนเครื่องสแกน เปลี่ยนความละเอียด หรือเปิด
   auto-crop ต้อง calibrate ใหม่ ห้ามข้าม

   **รูปถ่ายจากมือถือ: ทดสอบแล้วใช้ได้ (11 ก.ย. 2569)** ถ่ายกระดาษด้วยมือถือทั้ง 2 หน้า
   (ภาพ 1108x1477 ซึ่งเล็กกว่าใบอ้างอิง 1241x1754 และไม่ใช่สัดส่วน A4 เพราะติดพื้นหลังมาด้วย)
   `register.py` ยังจับคู่กับใบอ้างอิงแล้วดัดให้ทับได้สำเร็จ กรอบตัดคำตอบตกตรงช่อง
   **ครบทั้ง 12 ข้อ ลายมือไม่โดนตัด** ตรวจจริงทั้งใบได้ 14/15 ซึ่งตรงกับที่คนตรวจเอง
   (ข้อที่ได้ 0 คือเด็กตอบผิดจริง ไม่ใช่ระบบอ่านพลาด)

   แปลว่าพิกัดชุดนี้ไม่ได้ผูกกับ "เครื่องสแกน" อย่างเดียวอย่างที่กลัวไว้ — ตราบใดที่ยังจับคู่
   กับใบอ้างอิงได้ ก็ใช้ได้ทั้งไฟล์สแกนและรูปถ่าย **แต่ยังต้องรัน `tools/check_regions.py`
   แล้วเปิดภาพ crop ดูด้วยตาทุกครั้งที่เปลี่ยนวิธีถ่าย/สแกน** ใบเดียวผ่านไม่ได้แปลว่าใช้ได้ทั้งห้อง

   ข้อควรระวังเรื่องความละเอียด: ภาพที่ทดสอบมีขนาดไฟล์แค่ 0.2-0.3 MB ซึ่งถูกบีบมาแรง
   (น่าจะส่งผ่านแอปแชท) ยังอ่านออกเพราะลายมือตัวใหญ่และเขียนชัด ถ้าเจอลายมือเล็กหรือจาง
   ควรส่งไฟล์ต้นฉบับจากมือถือตรง ๆ ไม่ผ่านแอปที่บีบภาพ
7. **ยังไม่มีจุดอ้างอิงบนกระดาษ (fiducial marker)** นี่คือรากของข้อ 6 — ตอนนี้ระบบต้องเดา
   ตำแหน่งจากขอบกระดาษ ซึ่งใช้ไม่ได้กับไฟล์สแกน (กระดาษเต็มเฟรม ไม่เหลือพื้นหลังให้หาขอบ)
   ทางแก้ที่ทำให้พิกัดนิ่งข้ามเครื่องสแกนจริง ๆ คือพิมพ์ marker (QR/ArUco) ไว้ 4 มุมกระดาษ
   แล้วให้ `find_page_corners()` ยึดจาก marker แทน contour — เป็นงานที่ต้องแก้ข้อสอบต้นฉบับด้วย
   จึงยังไม่ได้ทำ
